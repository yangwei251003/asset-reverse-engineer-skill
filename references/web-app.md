# 网站、App 与小程序

用于网页截图、多状态界面、交互录屏、可访问网站、设计文件和现有源码。主交付物是可直接交给开发 Agent 的实现指令，而不是图像生成提示词。

## 先界定证据

明确输入属于：

- 单张截图：只能确认当前视口、视觉布局和可见状态；
- 多状态截图：可以确认状态之间的部分变化；
- 交互录屏：可以确认观察到的动作、动效、顺序和反馈；
- 可访问网站：可以检查响应式、真实交互、资源和运行行为；
- 项目源码：可以进一步确认组件、路由、数据流和技术约束。

不要从单张截图虚构后台逻辑、私有 API、数据库、登录权限、支付流程、隐藏页面或不可见交互。用户需要完整产品而证据不足时，将这些内容写成待实现需求或明确假设，而不是恢复事实。

## 提取高影响维度

- 页面目的、核心任务和主要用户；
- 视口、内容宽度、网格、层级、对齐、间距和留白；
- 字体、字号、字重、行高、颜色、边框、圆角、阴影和图像处理；
- 页面区块、组件边界、重复模式和设计令牌；
- 导航、按钮、表单、列表、弹层和反馈状态；
- 已观察到的 hover、focus、loading、error、empty、success 和过渡；
- 响应式变化、滚动、固定元素和断点行为；
- 素材、图标、图表、文案以及需要逐字保持的内容；
- 无障碍、性能和实现约束，只在目标需要时加入。

## 锚点与变量

忠实复刻锁定视觉层级、网格、关键尺寸关系、设计令牌、核心内容和已观察交互。增强只修改用户点名的可读性、层级、动效、无障碍或响应式等维度。

局部编辑要指定：

- 允许修改的页面、组件或状态；
- 必须保持的布局、路由、数据契约和邻近组件；
- 需要回归检查的桌面与移动视图。

## 开发 Agent 指令结构

按需包含：

1. 目标和证据范围；
2. 技术栈以及“沿用现有项目”要求；
3. 页面、区块和组件结构；
4. 设计系统与可复用令牌；
5. 响应式规则；
6. 已观察的交互、状态和动效；
7. 素材与逐字文案；
8. 明确的不得改动项；
9. 可运行、视觉和交互验收方法；
10. 未观察到但用户另行要求实现的功能。

不要默认生成大型 PRD、数据库设计、几十个文件的架构或未来扩展。让开发 Agent 先检查当前仓库和可复用组件，不覆盖无关代码。

## 提示词外证据

高保真复刻优先使用：

- 多视口截图和关键状态截图；
- 交互录屏；
- 字体、图标和图片原始资产；
- DOM、样式、设计令牌或设计文件；
- 可访问的真实网站；
- 项目源码及现有测试。

## 专用质量检查

- 是否清楚区分可见事实、合理推断和新增需求；
- 单截图是否被错误扩展成完整业务系统；
- 开发提示是否同时覆盖视觉、响应式、观察到的交互和验收；
- 是否沿用现有技术栈而非无依据重建；
- 是否包含足够素材说明，避免占位图或随意图标；
- 是否能用截图比较和交互测试验收，而不是只写“尽量一致”。
